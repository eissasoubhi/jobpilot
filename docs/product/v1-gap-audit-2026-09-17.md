# V1 gap audit — 2026-09-17

This audit reconciles the active V1 roadmap with code already present on `main` after the acquisition-matrix reviews were completed.

## Timeline evidence already delivered

The timeline is no longer a greenfield V1 gap. `main` already contains:

- an append-only `JobTimelineEvent` persistence model with offer/application links, event type, source, payload, `occurredAt`, and `recordedAt`;
- explicit business event types for offer import, source occurrence, preparation create/update, application submission, response, rejection, interview, and follow-up;
- timeline recording from canonical offer ingestion, application preparation, review decisions/application updates, and Gmail inbox classification;
- a read API covered by `ApplicationTimelineApiTest`;
- Gmail-to-timeline integration covered by `GmailInboxTimelineListenerTest`;
- frontend presentation through `web/lib/application-timeline.ts` and the application journey page;
- timeline-backed response-latency and discovery-to-application reporting services.

This means V1 Epic 3 should be treated as substantially delivered rather than restarted. Remaining work must be selected from concrete missing event coverage or user-facing workflow gaps, not by recreating the persistence foundation.

## Collection evidence

The acquisition matrix has no remaining `UNDER_REVIEW` entry after the Michael Page decision. The next collection work is implementation/maintenance of sources whose reviewed decision explicitly allows automated API/RSS/HTTP/browser collection. Sources restricted to Gmail/extension remain restricted; public visibility alone is not permission to scrape.

## Production evidence already present

The repository already contains production runbooks for deployment, backup/restore, monitoring/alerting, and incident response, plus a production baseline defining immutable images, controlled migrations, healthchecks, rollback, persistent PostgreSQL, object storage, secret management, and observability expectations.

Documentation alone is not production validation. Remaining hardening should therefore prioritize executable evidence: staging restore drills, immutable-image deployment verification, operational alerts, measured accessibility/performance, and environment-specific smoke/rollback validation.

## Revised V1 critical path

1. Close concrete timeline coverage gaps only where an existing user workflow can transition without a persisted business event.
2. Ensure follow-up tasks/reminders and Gmail responses cannot be lost and are represented by reliable timeline timestamps.
3. Finish CRM navigation/context gaps that are required from the Unified Offers Workspace; defer destructive organization merging until product rules are explicit.
4. Move temporal analytics to timeline timestamps exclusively and add only metrics with a stable business definition.
5. Complete production hardening with executable staging/production evidence rather than additional baseline prose.
6. Re-check Unified Offers Workspace parity before removing or redirecting the legacy Applications surface.

## Guardrails

- Do not invent an acceptance/final-result status solely to complete a roadmap checkbox; define the business state first.
- Do not weaken submission protections or auto-submit externally.
- Do not turn Gmail/extension-only sources into scrapers without new compliance evidence.
- Do not run migrations, fixtures, or E2E against development or production user data.
- V2 AI-first ATS and V3 Career OS remain future-only and do not contribute to V1 completion.
